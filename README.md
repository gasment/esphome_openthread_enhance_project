# ESPHome OpenThread & Thread BR <br>Enhance Project

* 此项目基于esphome为底板，依托esphome强大且方便集成的组件架构，拓展原有的OpenThread和OpenThread BR边缘路由功能，使其适应更多使用场景

* esphome在2026.11.0 dev版开始支持Thread Border Router组件，如只需基础BR功能，可以等待官方组件正式上线

* 乐鑫官方提供了ESP Thread Border Router/Zigbee Gateway的固件方案，你可以选择官方固件实现Thread BR功能

## 使用限制
* esphome版本不低于2026.10.2，高版本需要自行验证，如esphome版本更新导致编译与运行问题，建议退回到示列版本2026.10.2，也可等待项目更新修复
* 本项目未经大规模部署验证，仅用于学习研究与个人使用
* 本项目内各组件高度耦合，必须同一套使用，不能混用其他类似组件
* 本项目不考虑适配Thread市场商品，只针对运行esphome的ESP32 / nRF52840 设备

## 使用指导
参阅文档：https://esphome-openthread-enhance-pj.netlify.app/

### Summary 节点统计设备

HA 集成自动创建独立的 **Summary** 设备，与 BR 和代理节点并列，无父设备关联。包含“疑似离线设备”和“疑似电量设备”两个字符串传感器，状态均为 `异常设备数/代理节点总数`。

在 **BR 接入管理 → 代理节点 · 最近上报来源** 标题右侧点击 **统计设置**，可在同一弹窗中设置：

- 离线时长，默认 **30 分钟**。最近上报接收时间距离当前时间超过该值，计为疑似离线。
- 低电量依据：`battery`（默认低于 **20%**）或 `voltage`（默认低于 **3.0 V**），各自阈值分别保留。识别数值实体的 `device_class`，不依赖实体名称；电压会将 mV/µV/kV 换算为 V。

总数遍历本集成注册的代理节点设备，排除 BR、Summary、其他集成设备及已删除节点；同一节点不因多个实体或多个 BR 重复计数。同一节点任一有效匹配读数低于阈值即计为低电量，全部有效读数达到阈值才计为健康。缺少时间或有效电量读数的设备仍计入总数，但不计为对应的正常/异常状态，所以两者之和可能小于总数。

“疑似离线设备”的属性为浮点数 `suspect_offline`、`total`、`online`；“疑似电量设备”的属性为浮点数 `suspect_low_battery`、`total`、`battery_healthy`。使用最近一次收到的电量状态，不要求离线节点提供新采样。统计随节点上报、设备增删和设置保存刷新，并每 **30 秒**检查一次时长；设置及已有节点数据可跨 HA 重启保留。该功能无需修改节点或 BR 固件。
