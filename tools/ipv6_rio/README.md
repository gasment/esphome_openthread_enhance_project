# IPv6 RIO 用户态学习器

用于 Linux / DSM 无法直接学习 RIO 的场景。目标是接近 RFC 4191 的路由学习、
优先级和失效语义，不复制某台 NetworkManager 主机的 metric 或输出格式。
仅依赖 Python 3 标准库及支持 IPv6 `pref`、`expires`、多下一跳的 iproute2。
不需要 ESPHome，也不涉及固件编译。

## 运行

以下命令中的 `eth0` 仅为接口名称示例，使用时替换为实际接口。

观察模式（需要 raw socket 权限；会发送 RS、读取邻居表，不改路由或邻居表）：

```sh
python3 -u learn_routes.py --interface eth0
```

应用模式：

```sh
python3 -u learn_routes.py --interface eth0 --apply
```

现有服务的 `--interface <接口名> --apply` 参数可以继续使用。
正常停止旧服务后替换文件，再启动服务即可；本仓库修改不会自动部署到 DSM。

默认接受 `fc00::/7` 内的 RIO，前缀长度不再限定 `/64`，不学习默认路由。
可用 `--prefix` 重复限定范围，也可放宽到所有非组播、非链路本地前缀：

```sh
python3 -u learn_routes.py --interface eth0 --prefix ::/0 --apply
```

只有显式指定 `--allow-default-route`，才学习默认路由。此时先处理 RA 头部的
Router Lifetime / preference，再让有效的 `::/0` RIO 覆盖同一发送者的默认路由。
`--prefix ::/0` 本身不启用默认路由学习。PIO、SLAAC、DNS 继续由系统处理。

## 路由状态和选择

- 按 `(前缀, 路由器)` 分别保存 preference 和单调时钟到期时间。
- 每次 RA 只更新其中出现的 RIO；未出现的旧 RIO 不会被当作撤销。
- lifetime=0 只撤销对应发送者；RA 头部 Router Lifetime=0 不撤销非默认 RIO。
- 保留所有优先级候选。同前缀、同 preference 的候选安装为等权多下一跳。
- 显式写入 `proto ra` 和真实的 `pref high/medium/low`。
- `--metric` 默认 1024，high/medium/low 分别使用基准值、基准值+1、基准值+2。
  这是避免不同 preference 被内核合并为一个 ECMP 的兼容策略。metric 仍是本机
  路由管理策略，会影响与其他来源相同前缀路由的竞争，不是 RIO 报文中的字段。
- 内核负责最长前缀匹配、转发、ECMP 和普通邻居探测。脚本不按地址排序淘汰路由器。

每个通告保留独立寿命，有限寿命不截成一天，无限寿命不设置内核倒计时。
由于显式 ECMP 的 `expires` 是整组属性，一组路由使用最早成员的到期时间；
成员过期后脚本重建剩余下一跳。正常无阻塞时约有一个接收超时周期（1 秒）的
重建窗口，不会把短寿命成员延长到其他成员的到期时间。

## 邻居失效和恢复

默认每 5 秒读取一次内核邻居表，可通过 `--neighbor-interval` 调整。
只有 `FAILED` 视为已知失败；`STALE`、`DELAY`、`PROBE`、`INCOMPLETE` 或无记录
都不直接当作失败。

存在同前缀或覆盖前缀的其他可用学习路由时，暂时从安装集合中排除失败下一跳；
通告记录保留到期，可回退到低 preference 或较短的匹配前缀。
没有其他已知可用学习路由时，保留失败候选，允许实际业务触发内核重新解析。
此回退只考虑本脚本学到的前缀，不解释其他策略路由表或外部管理器的路由。

失败邻居再次发送合法 RA，且有仍有效的受支持通告和 Ethernet SLLAO 时，
应用模式会用其链路层地址将邻居重新置为 `STALE` 并标记为 router，恢复普通 NUD。
不会将未经请求的 RA 当作 `REACHABLE` 确认。没有 SLLAO 时依赖内核后续状态变化。

没有实现 RFC 4191 §3.5 中完整的“业务触发、每路由器限速”的优选路由器恢复探测，
不会以无条件周期 ping 替代。被排除的路由器恢复可能要等新的 RA 或邻居状态变化。
因此这仍是用户态近似实现，并非完整的内核 RIO 路径；普通 `ip route` 无法设置
所有内核原生 RIO 内部标志。

RS 在启动后随机延迟最多 1 秒，最多发送 3 次，间隔至少 4 秒，之后依赖 RA。
如确有需要，可通过 `--rs-interval 60` 启用持续 RS；默认不持续轮询路由器。

## 所有权、重启与兼容性

默认记录文件是 `/run/thread-rio-INTERFACE-TABLE.json`，可用 `--state-file` 指定。
它记录学习状态、已安装路由以及命令执行前的意图，采用原子替换更新。
同一次系统启动内，进程异常退出后可恢复原到期时间，不重新赋予完整 lifetime。
跨系统启动不复用单调时钟；正常退出会精确清理已安装路由。

脚本不执行协议级 `flush`。更新或删除前读取路由表，核对前缀、metric、protocol、
preference、全部下一跳、接口和权重。没有所有权记录的既存路由，即便内容一致，
也不会接管。发现占用或外部修改会告警并保留外部路由。

路由表没有通用的进程所有权标记：应避免其他服务同时管理相同前缀和这三个
metric。检查和修改之间不是原子事务，也无法识别外部删除后重建的完全相同路由。
同接口的第二个应用实例由文件锁阻止。不要在服务运行时删除记录文件。
修改 metric、table、interface 前先正常停止旧配置；若仍有未清理的所有权记录，
脚本会拒绝用不同配置解释这些记录。

旧版本的协议号 186 实际是 BGP。新版本不会批量清理它，以免删除真正的 BGP
路由。旧服务正常停止会执行旧版本自己的清理；若旧进程被强杀，则旧的有限路由
通常会自行过期，应核对具体前缀、下一跳和 metric 后再处理遗留项。

缺少 `pref`、`expires` 或 IPv6 多下一跳能力时，安装失败会明确记录错误；
不会静默退回一个固定网关。部署后可通过以下命令核对：

```sh
ip -6 route show proto ra
ip -6 neigh show dev eth0
```

两台 medium 路由器都有效时，应看到同一前缀的两个下一跳、`proto ra`、
`metric 1025`、`pref medium`，不要求与其他网络管理服务的 metric 或显示形式一致。

## 实机验收

已完成一次 DSM 双边界路由场景的实机验收，用户确认通过。
以下仅记录测试场景和结论，不包含实际网络地址、MAC、主机名、设备标识、
部署路径或原始日志。

| 测试场景 | 观察结果 | 结论 |
| --- | --- | --- |
| 两台边界路由器通告同一前缀，preference 均为 medium | 安装两个等权下一跳；`proto ra`、`metric 1025`、`pref medium` 正确，有限寿命倒计时可见 | 通过 |
| 断开其中一台边界路由器 | 对应链路本地邻居进入 `FAILED`，脚本将路由更新为仅保留另一台下一跳 | 通过 |
| 故障期间维持 Home Assistant 到 Thread 节点的连接 | 连接短暂中断后，通过剩余路径恢复；本次观察中断约 30 秒 | 通过 |
| 重新接入故障路由器 | 收到其有效 RA 后恢复双下一跳 | 通过 |

约 30 秒是本次端到端观测值，不是固定切换时间或性能保证。日志未同时记录
物理断开和邻居进入 `FAILED` 的准确时刻，不能据此拆分 NUD、脚本轮询和
应用重试各自的耗时，也不能将全部中断时间归于脚本。

本次实机验收覆盖正常学习、单路由器失效回退、业务恢复及路由器重新接入。
独立撤销/过期、不同 preference、无限寿命、异常退出恢复及外部路由冲突等
在开发阶段的 38 项离线测试中已通过验证，尚未据此宣称完成实机验收；
前述用户态实现限制仍然适用。

参考：[RFC 4191](https://www.rfc-editor.org/rfc/rfc4191.html)、
[Linux IPv6 route.c](https://github.com/torvalds/linux/blob/master/net/ipv6/route.c)。
